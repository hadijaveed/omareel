## Proposed submission body

Omareel is an open-source screen recorder for Omarchy. Record an area, window,
or screen with optional camera, microphone, and system audio. Reduce background
noise, save locally, and share a link from storage you control. Saved recordings
remain available to reopen, rename, upload, and share.

For everyday walkthroughs and video messages, it provides a Loom-style workflow
from the Omarchy bar. Optional Studio adds Screen Studio-style finishing for
demos and tutorials: click-triggered zooms, backgrounds, frames, spacing, and
canvas shapes. It exports a separate styled MP4 and copies the recorded audio
without processing it again. Quick recordings can still go straight to sharing.
These comparisons describe the workflows; they do not imply feature parity.

No Omareel account or subscription is required. Keep videos on your machine,
use an existing cloud bucket, or host the video and player on your own storage.
Provider charges and access configuration remain the user's responsibility.

### Security and permissions for review

This update carries forward the fixes from the
[accepted 0.9.2 snapshot](https://github.com/omacom/omarchy-plugin-marketplace/issues/5763#issuecomment-5694488940).
That approval applies to its exact commit, not to the new Studio code. Please
review the final 0.9.3 commit and its changes separately.

- **Explicit installation:** loading the plugin does not install a CLI shortcut.
  Linking requires an explicit action and refuses conflicting or unsafe paths.
  Runtime performs no privilege elevation or package installation; package
  commands in the README are instructions for the user.
- **Runtime and settings files:** checked ownership, no-follow file handling,
  private runtime permissions, checked locks, and atomic replacements protect
  these helper paths. JSON/settings, PID, log, and other runtime data have fixed
  byte limits. These limits are not limits on video size.
- **Stop and recovery:** unusable settings do not prevent Stop from saving
  locally. Recovery retains the raw take, reports the problem, and avoids
  automatic upload.
- **Untrusted UI text:** device names, titles, paths, and process errors are
  rendered as plain text rather than interpreted as rich-text content.
- **Studio click capture:** explicitly enabled click zoom installs a temporary,
  non-consuming desktop binding during a recording. It records click times and
  positions within the capture region; the helper does not collect keystrokes
  or typed text. The screen recording itself still records visible content.
  Session checks restrict collection to the active take, and cleanup attempts
  to disable the binding when recording ends. No persistent desktop-config edit
  is required.
- **Local rendering and optional networking:** Studio renders with local FFmpeg.
  Sharing uses the user's configured storage destination. Optional voice-model
  downloads use pinned revisions and checksum verification. Model setup and
  upload are separate from local rendering. Studio pauses automatic uploads
  while the user reviews the take.
- **Public-link limits:** generated player pages request `noindex`, which
  cooperative search engines honor. Public links are not authenticated private
  pages; this cannot prevent all crawling, access, or redistribution.

### Compatibility and validation

Targets Omarchy Quattro (4.0) and later on its Hyprland/Quickshell stack.
Other Linux desktops and all future Omarchy versions are not verified by this
submission. Studio currently provides a still-frame preview and SDR H.264 export
up to a 3840-pixel long edge. Click zoom is unavailable for portal Window capture.
The current live camera view can be cropped by zoom in the exported video.

## Internal checks before submission — not marketplace copy

The initial Studio source inspection found gaps relevant to the maintainer's
earlier memory-exhaustion concern. The inherited runtime helper's protections
do not automatically cover every new Studio input:

- `bin/studio.py:recording_capture` buffers the entire recording index with
  `read_text().splitlines()`. Add bounded reading and validation of capture
  metadata, including malformed records and oversized click lists.
- `prepare_camera` reads the camera timestamp without a byte limit. Bound and
  validate that read, including rejection of unsuitable file types.
- `run` uses `communicate()` to buffer subprocess stdout and stderr without a
  ceiling. Truncating the resulting error message afterward does not bound the
  original allocation. Bound collection and test noisy/malformed-media failures.
- Recheck all Studio media inputs, metadata paths, subprocess handling, and
  click-binding cleanup. Source inspection here is not a comprehensive audit.

The previous Studio candidate's CI failed because Ubuntu's older FFmpeg rejects
`-/filter_complex`. This branch now includes a compatibility fallback and
regression test; 23 Studio regressions and native Studio checks passed locally
after that change. CI verification is still required on the updated candidate.
Do not call GitHub CI green without checking that exact commit.

Physical microphone/camera playback checks on multiple laptops remain pending.
Include basic recording with Studio off in that testing, plus Stop, local saves,
library actions, and upload failure handling. Synthetic tests do not establish
physical-device compatibility or voice quality.
