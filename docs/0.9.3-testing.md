## Put this candidate on another laptop

The development candidate is shared on `feat/studio-mode` for testing through a
draft source PR. Use the same commit on each laptop and record its SHA; the
branch may advance as issues are fixed. First stop recording/exporting.

For an existing clean Omareel installation:

```bash
cd ~/.config/omarchy/plugins/hadijaveed.omareel
git status --short                          # must be empty; preserve edits first
git branch backup/before-studio-0.9.3        # choose a new name if it exists
git fetch origin feat/studio-mode
git switch -c test/studio-0.9.3 FETCH_HEAD
./bin/omareel setup --link
omarchy plugin validate .
omarchy restart shell                      # desktop must be unlocked
omareel config merge '{"studio":{"enabled":true,"zoomOnClicks":true}}'
omarchy-shell omareel open
```

For a fresh machine, install public Omareel using the README first, then switch
the clean checkout with the steps above. Record the candidate's `git rev-parse
HEAD`, `omarchy version`, GPU/driver, display scale, mic, and camera in the matrix.
No cloud credentials belong in a test report. For offline transfer, create a
bundle with `git bundle create /tmp/omareel-studio.bundle feat/studio-mode` on
the source machine, then replace `origin` in the fetch command with that bundle's
path on the test laptop.

To return to the version saved before testing, stop recording/exporting and
switch to `backup/before-studio-0.9.3`, then restart the unlocked shell. Settings,
recordings and credentials remain outside the checkout; originals and exported
MP4s remain playable. Keep Studio sidecars if you want to restyle those takes.

## A useful first test: 30 seconds

1. Enable Studio and Zoom on clicks. Choose the mic and camera you normally use.
2. Record an Area. Speak a sentence with a quiet ending, pause, then speak again.
   Click three well-separated controls, including one near an edge; type and
   move the pointer between them. The camera must stay visible while recording.
3. Stop from the bar. Confirm Studio opens after cleanup and the original saves.
4. Export Midnight. Play the full video: check zooms occur at clicks, return
   smoothly, preserve motion, and keep speech/camera synchronized.
5. Compare voice and pauses in original versus Studio export. Try Paper and a
   portrait canvas. Reopen the original and check it is unchanged.
6. Change Frame and Spacing in Adjust, close Studio, and make another take.
   Verify the same choices return without a separate save step, including after
   restarting the unlocked shell. Reset should also persist.
7. Turn Zoom on clicks off and repeat. Then turn Studio off and record once.
   Neither should leave a stuck Stop control or unexpected zooms.

Then repeat Window and Screen, the keyboard Stop shortcut, other camera positions,
and the display scales used on that laptop. Try missing camera, a canceled
picker, and a failed export; every failure must leave a clear path back to a
saved original. Run Upload/Test upload only with an explicitly chosen test
bucket; verify the selected original/styled copy and player link.

## Known limits to decide before release

- Camera is baked into current KMS recordings: click zoom can crop it in the
  export. A fixed camera throughout zoom is not implemented for new takes.
  Decide whether this is acceptable for 0.9.3; otherwise it blocks that promise.
- Preview is a still frame, not motion playback. Inspect the exported video.
- Click capture supports direct Area/Window/Screen, not portal Window.
- Export is SDR H.264, up to 3840 pixels on the long edge, rendered on the CPU.
  Check time, disk use, and quality at the laptop's usual recording resolution.
- Natural/Clean/Strong need listening checks for quiet endings and pauses.
  Audio packet equality proves Studio doesn't reprocess sound; it doesn't prove
  the capture/cleanup sounds good on every microphone.

### Automatic Studio preferences follow-up

The native UI check now rapidly changes Frame/Spacing/Shadow/Canvas while a
previous settings write is deliberately slowed, then verifies the last selection
in the settings file. A second Quickshell process restores it and checks the
visible control values. Reset, a simulated write failure and Retry save are
covered. Other Studio toggles, mic, sharing and output settings are preserved.

### Settings and Stop follow-up · 2026-09-11

The Studio integration passed settings-security (12), workflow (10), Studio (22)
and audio (10) tests. Native tests passed for settings loading/atomic updates,
symlink rejection, startup with invalid settings, both Stop handlers, Studio
style persistence/retry/export and compositor click cleanup.

The installed testing copy also recorded a synthetic moving window with Studio
and click capture enabled. After deliberately corrupting only its isolated
settings file, the production bar Stop handler saved locally, retained the raw
and original takes, and left the invalid settings untouched. Restoring the
fixture settings allowed Studio export; the renderer recognized the captured
click zoom. The exported MP4 was playable (3.27 seconds, seven distinct sampled
frames). No camera or microphone was used, so the physical-device and listening
checks in the matrix above remain required.

### Runtime size limits follow-up

The stable size-limit fix passed all 119 Python regressions and both GitHub CI
runs. The 13 limit cases cover 8 GiB sparse files under a 64 MiB memory ceiling,
oversized pipes without EOF, growing files, exact boundaries, preserved previous
files and concurrent capped log rotation. Native bar/panel tests reject unsafe
or oversized state at startup and after startup. The Studio integration also
checks that a completed take still opens Studio automatically.

The installed Studio copy passed real GPU capture → Stop → click-zoom preview →
export on Omarchy 4.0.1. A second take combined corrupted fixture settings and an
oversized log during recording; rotation and Stop succeeded, originals were
retained, and Studio exported a playable 3.8-second MP4 with eight distinct
sampled frames. The native Studio test also passed automatic style persistence,
fresh-process restore and retry. Camera/microphone capture was disabled for
these synthetic-window takes; the physical-device/listening matrix still applies.

One test start initially sampled the test window while it extended outside the
monitor. The recorder rejected the region and preserved a clear startup error.
The harness now waits for stable geometry fully inside the display; the rerun
passed. This was a test setup correction, not a change to capture geometry.

Hadi approved the README/submission copy and reported that local testing of
installed candidate `543ad15` was good. This is user-reported playback approval
for the current machine, not evidence of tests on additional physical laptops.
The follow-up code changes concern bounded metadata/subprocess handling and

The Studio suite now covers the identified input-limit gaps, malformed click
