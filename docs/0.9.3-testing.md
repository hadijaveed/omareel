# 0.9.3 Studio: testing and release plan

**Status: development preview, not approved for release.** Source branch:
`feat/studio-mode`. Development manifest: `0.9.3-dev`. Public 0.9.2 is the
compatibility hotfix and contains no Studio code.

## Release order

1. Wait for the [0.9.2 marketplace update](https://github.com/omacom/omarchy-plugin-marketplace/issues/5763) to be approved and published.
2. Test the same Studio candidate on multiple physical laptops, including
   Quattro 4.0.0 and the newer supported Omarchy version. Record results below.
3. Resolve release-blocking failures and have Hadi approve picture, camera,
   zoom, and voice quality. Update screenshots if the visible workflow changes.
4. Change the version to `0.9.3`, finalize the README/release notes, and open the

5. Submit the marketplace update for the exact final commit and await review.

No main merge, tag, GitHub release, or maintainer submission is authorized by
this preparation step. Development screenshots and copy are not evidence of
physical-device compatibility.

## Put this candidate on another laptop

Until the branch is shared for testing, use a Git bundle from this checkout.
This avoids publishing unfinished Studio code. First stop recording/exporting.
On the source machine, after committing the candidate:

```bash
git bundle create /tmp/omareel-studio.bundle feat/studio-mode
```

Transfer that bundle to `/tmp/omareel-studio.bundle` on the test laptop. For an
existing clean Omareel installation:

```bash
cd ~/.config/omarchy/plugins/hadijaveed.omareel
git status --short                          # must be empty; preserve edits first
git branch backup/before-studio-0.9.3        # choose a new name if it exists
git fetch /tmp/omareel-studio.bundle feat/studio-mode
git switch -c test/studio-0.9.3 FETCH_HEAD
./bin/omareel setup --link
omarchy plugin validate .
omarchy restart shell                      # desktop must be unlocked
omareel config merge '{"studio":{"enabled":true,"zoomOnClicks":true}}'
omarchy-shell omareel open
```

For a fresh machine, install public Omareel using the README first, then switch
the clean checkout with the steps above. Record the candidate's `git rev-parse
HEAD`, `omarchy version`, GPU/driver, display scale, mic, and camera in the matrix.
No cloud credentials belong in a test report or Git bundle.

To return to the version saved before testing, stop recording/exporting and
switch to `backup/before-studio-0.9.3`, then restart the unlocked shell. Settings,
recordings and credentials remain outside the checkout; originals and exported
MP4s remain playable. Keep Studio sidecars if you want to restyle those takes.

## A useful first test: 30 seconds

1. Enable Studio and Zoom on clicks. Choose the mic and camera you normally use.
2. Record an Area. Speak a sentence with a quiet ending, pause, then speak again.
   Click three well-separated controls, including one near an edge; type and
   move the pointer between them. The camera must stay visible while recording.
3. Stop from the bar. Confirm Studio opens after cleanup and the original saves.
4. Export Midnight. Play the full video: check zooms occur at clicks, return
   smoothly, preserve motion, and keep speech/camera synchronized.
5. Compare voice and pauses in original versus Studio export. Try Paper and a
   portrait canvas. Reopen the original and check it is unchanged.
6. Turn Zoom on clicks off and repeat. Then turn Studio off and record once.
   Neither should leave a stuck Stop control or unexpected zooms.

Then repeat Window and Screen, the keyboard Stop shortcut, other camera positions,
and the display scales used on that laptop. Try missing camera, a canceled
picker, and a failed export; every failure must leave a clear path back to a
saved original. Run Upload/Test upload only with an explicitly chosen test
bucket; verify the selected original/styled copy and player link.

## Known limits to decide before release

- Camera is baked into current KMS recordings: click zoom can crop it in the
  export. A fixed camera throughout zoom is not implemented for new takes.
  Decide whether this is acceptable for 0.9.3; otherwise it blocks that promise.
- Preview is a still frame, not motion playback. Inspect the exported video.
- Click capture supports direct Area/Window/Screen, not portal Window.
- Export is SDR H.264, up to 3840 pixels on the long edge, rendered on the CPU.
  Check time, disk use, and quality at the laptop's usual recording resolution.
- Natural/Clean/Strong need listening checks for quiet endings and pauses.
  Audio packet equality proves Studio doesn't reprocess sound; it doesn't prove
  the capture/cleanup sounds good on every microphone.

## Automated checks for each candidate

Run the setup, workflow, audio, upload, text-security and Studio regression
suites, `node tests/helpers.js`, `bash -n bin/omareel`, and manifest validation.
On each supported Omarchy version, run:

```bash
python3 tests/shell-actions-native.py
python3 tests/studio-native.py
python3 tests/click-zoom-native.py
```

The click test temporarily installs a non-consuming compositor callback and
verifies cleanup/existing bindings. Run it while no recording is active. These
checks use temporary fixtures; none replace the physical take and listening test.
