# Omareel 0.9.4 — idle CPU hotfix

Fixes an idle feedback loop in the bar and recording panel. Both watch the
runtime directory and refresh status when it changes. Status initialization
used to call `fchmod(0700)` every time; Linux emits an attribute-change event
even when the mode already equals 0700, triggering another status process.

Runtime initialization now changes permissions only when necessary. Ownership,
path, symlink, and shared-write checks still run first. Safe, owned legacy 0755
directories still tighten to 0700. Atomic state writes still refresh both UI
components, and basic recording, sharing, and Studio remain included.

Two real-inotify regressions cover quiet repeated status reads and one-time
legacy permission repair. An unchanged `chmod` is a positive control, proving
the test can detect this failure. The existing runtime security suite runs in
CI. Native checks also verify that both production status readers settle after
an atomic update instead of continuously spawning processes.

The test for quiet repeated status reads failed on 0.9.3 and passed with the
fix. All 23 runtime security tests and 13 runtime-limit tests passed locally,
as did native bar/panel updates, idle settlement, and hostile-path checks.

This corrects the identified loop; future runtime changes must keep reads free
of directory-change notifications. It is not a guarantee against unrelated
sources of CPU load. Marketplace verification applies separately to the exact
hotfix commit.
